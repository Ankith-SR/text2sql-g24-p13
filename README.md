# Text2SQL (CSE 573, Group 24 / Project 13)

Turn plain-English questions into executable SQL, evaluated on **Spider 1.0** and **BIRD**.
We compare three tiers of systems under identical conditions, then build our own pipeline:

| Tier | System |
|---|---|
| 1 | Heuristic keyword / schema matching (`baselines/heuristic.py`) |
| 2 | LGESQL, classical neural (reproduced from its public code, see `docs/LGESQL.md`) |
| 3 | Prompted open LLMs: Qwen2.5-Coder-7B, Llama-3.1-8B (0-/3-shot), plus a larger open model via ASU Voyager |
| Ours | Schema pruning → QLoRA-tuned Qwen2.5-Coder-7B → N samples → execution voting (4-step tie-break) → repair (up to R) |

Team: Ankith Subramani Radha, Divyesh Kamleshbhai Patel, Harshan Karadaguru Anjaneyareddy, Hui Yu Teng.
Docs: [proposal](docs/proposal.pdf) · [presentation](docs/presentation.pptx) · [evaluation protocol](docs/EVALUATION.md) · [task board](docs/TASKS.md) · [git workflow](CONTRIBUTING.md)

## Quick start
```bash
git clone https://github.com/<org-or-user>/text2sql-g24-p13.git && cd text2sql-g24-p13
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # add requirements-train.txt on a GPU box
cp .env.example .env                     # fill in VOYAGER_API_KEY if you use ASU Voyager
make test                                # unit tests, no data or GPU needed
make demo                                # works right away on data/samples/college with backend "heuristic"
```

Local LLM (Ollama):
```bash
brew install ollama        # or https://ollama.com/download
ollama serve &             # keep running
ollama pull qwen2.5-coder:7b && ollama pull llama3.1:8b
```

Spider: download from https://yale-lily.github.io/spider into `data/spider/`, then `bash scripts/setup_data.sh`.

## Running the experiments
```bash
make heuristic                    # Tier 1, full Spider dev
make baselines                    # Tier 3, every model, 0-shot and 3-shot
make pipeline                     # ours, first 200 dev questions
make ablations                    # prune / vote / repair on-off (+ --sweep for N, R)
python scripts/error_analysis.py --run runs/llm-spider-qwen2.5-coder_7b
make summary                      # -> evaluations/results_summary.md + figures
```
Each run writes `runs/<name>/{preds.json,details.json,metrics.json,run_record.json}`; only the
two small JSON files are committed (and copied into `evaluations/` by `make summary`).
Smoke-test anything first with `--limit 20`. Fine-tuning and serving the QLoRA model:
[docs/QLORA_SERVING.md](docs/QLORA_SERVING.md).

## Demo
`make demo` opens http://localhost:8501. Pick a database (toy sample, Spider sample, or every Spider dev DB once downloaded), an example question or your own, and a backend (Ollama / Voyager / vLLM, or the heuristic for offline use). It shows:
the generated SQL and result table; correctness against the gold SQL for dataset questions;
every candidate with its result group, votes, log-prob and which one was chosen; repairs used,
which tie-break rule decided, latency and number of model calls; the (pruned) prompt.
